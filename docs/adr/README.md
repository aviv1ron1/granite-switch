# Architecture Decision Records

ADRs document significant, irreversible-ish architectural decisions and the reasoning
behind them. Each ADR is immutable once accepted — to change a decision, write a new
ADR that supersedes the old one.

## Format

MADR-lite: Status, Context, Decision, Consequences, Alternatives. Keep them short and
concrete. The point is to capture *why*, not to write a tutorial.

## Naming

`ADR-NNN-short-title.md`, where `NNN` is the next sequential number (zero-padded).
